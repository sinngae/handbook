## 表达能力
对于每个问答的考量因素、技术机制、优化思路，要多次过脑至清晰可现可表，有条理地表述
+ 常见的表达问题
    + 专业和经验的深度越广、越深，越难表述？
    + 写得多 说的少，不利索？
    + 说起来，没有铺垫、重复啰嗦、跳跃、回旋往复
+ 基本法则
    + 先总后分、先整体再局部
    + 先基本思路，实现，再说优化
    + 互动，（对于大的课题，几个小时讲不完）先综述，再问对方“想听哪个”（选几个讲）来分述
        + 如系统设计的场景题，多问一些要求（时间、空间、多大数据量、并发量、特殊情况的考虑等）
+ 项目经验的表述，尽量详尽
    + 项目的技术栈、技术决策原因及技术细节
    + 提前准备印象最深刻、理解最深刻、最具有代表性的系统和项目，详尽的细节、经得起反复琢磨的
    + 选择熟悉的项目和架构，至少有好的第一印象，不然给人印象就是啥也没深入思考过

# 面试与被面试的博弈
> 职业竞争的基本法则是稀缺性（上策），差异化是稀缺性的一个快捷路径（中策），降格以求是快速找份工作的代价（下策）。
> 工程师面试的深度和广度极大，从基础算法 到各种中间件的原理机制 再到实际运维架构，除非平常就做了非常深且广的沉淀，不然太难尝试成功。
> 外界的认可固然重要，内在的自尊向上的可贵性远胜外在
> 遵循市场规律，用实力使人信服

+ 中高端职位
    + 企业对大龄员工期望更高
        + 个人以面试 技术专家/架构师 的准备来求职 高级工程师
    + 带团队的经历
    + 多少架构设计的时间
    + 架构过程是怎样的，有哪些架构设计思想或方法论
    + 岗位的业务和之前的工作经历是否有切合
+ 面试者好的心态
    + 不必急于求成，抱着检测自己的不足的心态
        + 发现不足的收益 远大于 找到一份工作
        + 自尊，外界的认可固然重要，内在的自尊向上的可贵性远胜外在
        + 惜其无缘，亦不可强留
        + 焦虑，来源现实和目标的差距
    + 目标可行，做出合理决策，然后持续投入、恰当的出击（搏斗）来实现目标
        + 决策、持续努力、掌握基本面、出击能力都是可以持续修炼的
        + 决策的合理性
            + 个人评估不了10年、5年的目标的合理性比较难，但是一年2年的目标如何达成还是可以的。
    + 年龄的偏见，除了企业不招大龄程序员，还有大龄人员一定比年轻人更好用或更不好用
    + 遵循市场规律，具备使人信服的实力
    + 不局限在一个企业或所有企业的范围内创造价值
    + 专注于双向沟通
        + 让对方充分认知和了解，赢得对方的认可和信服
        + 了解对方，抓住提问的重点
+ 公司和岗位选择
    + 志趣和驱动力
    + 薪资待遇
    + 公司发展前景和个人发展空间
    + 工作氛围
    + 小而有战斗力的企业

## 面试官
+ 多个面试官合起来问的就是一个面
    + 技术基本面的广度和深度
    + 管理方面的总结
    + 设计方面的总结
    + 生产问题排查的总结
+ 面试通过有限时间的沟通了解双方，有其局限性
    + 有限的时间，再有经验也会走眼
    + 运气、双方的情绪
    + 面试官的水平

## 面试答题
+ 证明自己的对技术的深度、对原理的深层次理解
+ 系统性思维，不局限于具体业务，对关联业务的了解、对整体的思考
+ 多元思维，除了开发和测试，对运维、产品、业务、商业层面的思考
+ 管理经验，团队影响力
+ 稀缺能力，大型项目的架构设计、技术难题攻克、精通某个高端技术领域
+ 差异化，做事缜密周全精细化、有高并发流量系统开发和维护经验
    + 凸显自己的优势领域
+ 工程质量、性能优化、稳定性建设、业务配置化设计
+ 定量描述作为实证，请求量、优化后
    + 凸显贡献，赢得认可
+ 过往经历的复盘，每段经历、经历的收获
