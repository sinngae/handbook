# 一句话结论
**管道、共享内存、消息队列、信号量这些传统IPC仍然在大量使用，并没有被淘汰；UDS（Unix Domain Socket）只是IPC其中一种，不是万能替代品，有它适用场景，也有短板。**

先理清分类，再对比选型：
## 一、传统IPC体系（POSIX / System V）
1. **管道 pipe / 命名管道FIFO**
    - 本质：单向字节流，简单、内核自动同步。
    - 适用：父子进程简单单向数据流。
    - 缺点：只能字节流，不自带消息边界；pipe只能亲缘进程。
2. **共享内存 shm**
    - 速度**最快**，直接映射同一块物理内存到多个进程虚拟地址，没有内核拷贝。
    - ⚠️ 本身**不带同步**！必须搭配信号量/互斥锁，否则竞态。
    - 适合：大数据传输（日志、大帧、视频流）。
3. **消息队列（System V msgq / POSIX mq）**
    - 带消息边界、消息类型，支持按类型取消息，异步缓存。
    - 缺点：有系统全局上限，数据要在内核缓冲区拷贝，性能弱于shm。
4. **信号量 semaphore**
    - 不是用来传数据的！**只做同步、互斥**，保护共享内存/资源。
5. **信号 signal**
    - 极简通知，几乎不能传复杂数据，适合事件中断。

## 二、UDS（Unix Domain Socket）
UDS是**socket的本地版本**，不走网卡、不经过协议栈，内核直接拷贝，支持 `SOCK_STREAM`（流式，类似TCP）和`SOCK_DGRAM`（报文，自带消息边界）。
✅ 优点：
1. API统一，和网络socket几乎一样，上手简单；支持多进程/多客户端连接，**亲缘、非亲缘进程都能通信**。
2. 自带内核同步、消息边界（dgram），天然隔离，不容易出现共享内存那种数据竞争。
3. 可以传递**文件描述符**！这个是UDS独有的大招，进程间传递fd（套接字、文件句柄），传统pipe/shm做不到。

❌ 缺点：
1. 数据需要在内核缓冲区拷贝，**大数据吞吐量不如共享内存**。每次读写都要用户态<->内核态拷贝。
2. 基于文件路径，需要管理文件权限、清理socket文件（进程crash容易残留文件）。
3. 多生产者并发读写虽然安全，但高频小包场景，开销高于信号量+shm组合。

> 误区：UDS 并不是“替代全部IPC”，它只是**易用性很强的IPC**，适合请求应答式、小/中等数据、需要fd传递的场景。

# 三、现代并发程序怎么选（进程间，注意：是**进程间**，不是线程间！）
> 重点区分：**线程间不需要IPC！** 同进程线程天然共享虚拟内存，直接用 mutex/cond、channel（Go）、原子变量，开销远低于任何IPC。IPC是**跨进程**才需要。

### 场景1：进程之间，少量消息、请求响应、服务通信（最常见）
👉 **优先 UDS**
比如：daemon守护进程、本地agent、服务和本地sidecar通信（很多云原生本地组件、容器内部进程通信都用UDS）。
例如：docker daemon / containerd、kubelet本地通信都大量UDS。

### 场景2：进程之间传输**超大块数据**（几MB~GB级）
👉 **共享内存 + 信号量/互斥锁**
视频帧、大缓存、数据库进程内部大块数据交换。UDS反复拷贝会带来明显CPU开销。

### 场景3：简单单向流式数据、父子进程
👉 pipe 最省事，最简单轻量，不需要文件。

### 场景4：需要异步消息队列、带消息优先级、持久化需求
👉 POSIX消息队列，或者直接上外部MQ（redis、kafka，不再是原生IPC）

### 场景5：只做事件通知，不传数据
👉 signal / eventfd（Linux特有，现代很常用，轻量事件通知，很多Go/runtime底层在用）

# 四、现代工程上的变化
1. **System V 老式IPC（老消息队列、老信号量）现在慢慢少用**，容易出现资源泄露，ipcs命令手动清理；新项目优先 POSIX IPC、eventfd、UDS。
2. eventfd 是Linux现代轻量IPC，很多人忽略：只做事件计数通知，开销极低，常用于epoll+跨进程唤醒，高性能网关、runtime大量使用。
3. 很多语言封装屏蔽底层：Go net包直接支持UDS；C++/Rust也都原生支持，所以业务开发感觉UDS“更好写”，但底层性能边界要清楚。

# 五、一张简单对比
| IPC | 是否传数据 | 核心优势 | 短板 |
|---|---|---|---|
| Pipe/FIFO | ✅字节流 | 极简 | 单向，无消息边界 |
| 共享内存 | ✅直接内存 | 速度最快 | 无同步，需要锁 |
| POSIX消息队列 | ✅消息 | 消息边界、异步 | 内核拷贝，有上限 |
| UDS | ✅流/报文 | API通用，支持传fd | 大数据有拷贝开销 |
| Sem / eventfd | ❌仅同步通知 | 极轻量 | 不能携带业务数据 |

# 六、补充面试常问区分
- 线程间：**不需要IPC**，共享地址空间，用锁、原子、条件变量。
- 进程间：地址空间隔离，必须IPC，根据数据大小、是否需要fd传递选型。
- UDS本质还是socket，**只能本机**，不能跨机器；跨机器才走TCP socket。
