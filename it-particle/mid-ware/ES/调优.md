# 从ES查询数据，为何会不精准
Elasticsearch 查询结果不精准的原因主要有以下几点：

### 1. 分片机制导致聚合结果不精确
Elasticsearch 的数据分布在多个分片上，聚合查询时，每个分片会独立计算 Top X 结果，然后汇总到协调节点上进行最终计算。这种机制在数据量较大时可能导致结果不精准。例如，某些分片上的数据可能未被充分考虑，从而导致最终结果偏差。

解决方案：
- 调整 `shard_size` 参数，使其大于等于 `size` 参数，通常设置为 `size * 1.5 + 10`。
- 如果对精度要求极高，可以将 `size` 设置为分片支持的最大值，但这会严重影响性能。

### 2. 分词器和字段类型问题
Elasticsearch 默认的分词器（如 `standard`）会将中文内容拆分成单字，导致无法直接查询完整的中文短语。此外，`text` 类型字段用于全文搜索，而 `keyword` 类型字段用于精确匹配，如果查询时未正确使用字段类型，也可能导致结果不精准。

解决方案：
- 使用 `keyword` 后缀查询，例如 `QueryBuilders.termQuery("field.keyword", "查询中文内容")`。
- 使用支持中文的分词器，如 IK 分词器。

### 3. 查询条件和查询方式问题
- 通配符查询：通配符查询（如 `*` 和 `?`）可能导致全表扫描，尤其是在通配符出现在开头时，严重影响查询性能。
- 深度分页：当使用 `from` 和 `size` 参数进行分页查询时，如果 `from` 值很大，会导致查询效率大幅下降。

解决方案：
- 避免使用前缀通配符查询。
- 使用滚动查询（Scroll API）或深度分页优化。

### 4. 数据刷新策略
Elasticsearch 默认每秒执行一次刷新操作，因此文档的实时性被提高到 1 秒。这意味着在数据写入后，可能需要等待 1 秒才能查询到。

解决方案：
- 在写入时指定刷新策略，例如 `request().setRefreshPolicy(RefreshPolicy.IMMEDIATE)`。

### 5. 查询优化不足
未优化的查询可能导致查询结果不精准或性能问题。例如，未正确使用过滤器（`filter`）和查询（`query`）的顺序，可能导致查询效率低下。

解决方案：
- 优先使用过滤器（如 `term` 和 `range`），因为它们可以被缓存。
- 避免使用低效查询，如深度分页和通配符查询。

通过以上方法，可以有效解决 Elasticsearch 查询结果不精准的问题，并提升查询性能。

# ES查询平均耗时
在Elasticsearch中，查询平均耗时受多种因素影响，包括集群配置、查询类型、数据量和索引设计等。以下是一些关于查询平均耗时的常见情况和优化建议：

### 查询平均耗时的常见范围
- 毫秒级响应：在优化良好的集群中，对于简单的查询（如精确匹配的`term`查询），平均耗时通常在10-50毫秒。
- 秒级响应：对于复杂的查询（如全文搜索、聚合查询或深度分页），平均耗时可能在1-5秒。
- 高并发场景：在高并发查询时（如200并发），平均响应时间可能会显著增加，例如从几十毫秒增加到几百毫秒甚至几秒。

### 影响查询平均耗时的因素
1. 集群配置：
   - 集群节点数量和硬件配置（如CPU、内存、磁盘类型）直接影响查询性能。增加节点数量和升级硬件规格可以显著降低查询耗时。
   - 例如，在单节点集群中，10并发检索的平均响应时间为77毫秒，而在10节点集群中，相同并发量的平均响应时间可降低到21毫秒。

2. 查询类型：
   - 精确查询（如`term`、`range`）通常比全文查询（如`match`）更快。
   - 聚合查询和深度分页可能导致较高的查询耗时，尤其是在数据量较大时。

3. 索引设计：
   - 合理的分片和副本设计可以提升查询性能。例如，将分片副本数调整为节点数的倍数，可以实现负载均衡。
   - 索引的`refresh_interval`和`flush`设置也会影响查询性能。

4. 数据量和缓存：
   - 数据量越大，查询耗时可能越长。通过优化数据存储（如仅存储用于检索的字段）和利用文件系统缓存（`filesystem cache`），可以显著提升查询性能。

### 优化查询性能的建议
1. 开启慢查询日志：通过设置慢查询日志的阈值，可以捕获耗时较长的查询并进行分析。
   ```json
   PUT */_settings
   {
       "index.search.slowlog.threshold.query.warn": "500ms"
   }
   ```
2. 使用`filter`子句：在`bool`查询中，尽量使用`filter`子句代替`query`子句，因为`filter`结果会被缓存。
3. 优化查询语句：将`terms`查询替换为多个`term`查询，可以提高性能。
4. 调整集群配置：增加集群节点数量和升级硬件配置，可以显著提升查询性能。
5. 控制索引数据量：仅存储用于检索的字段，减少不必要的数据存储，以充分利用文件系统缓存。

通过以上优化措施，可以有效降低Elasticsearch查询的平均耗时，提升查询性能。
