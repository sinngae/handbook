# 一、概念总图（关系一览）
> 从底层身份数据 → 认证授权协议 → 凭证载体，全部串起来

```
【IDM 身份生命周期管理】（IAM子集）
    ↓ 负责：用户/账号/角色的生、老、病、死；主数据维护；SCIM同步；权限审计
    ↓ 输出：身份主数据（用户id、部门、角色、邮箱）
    ↓ 供给给
【IAM 身份访问管理平台(IdP 身份提供商)】
├─ IDM模块（上面的账号生命周期）
└─ AM 访问管理模块（认证+鉴权，核心！）
        ├─ 认证能力：密码、MFA、生物识别
        ├─ 协议栈：
        │   ├ OAuth2 【授权协议】—— 只做资源授权，本身不证明是谁
        │   └ OIDC(OpenID Connect)【基于OAuth2的身份认证协议】
        │        → OIDC 强制输出 ID Token，格式固定为 JWT
        ├─ 令牌/凭证体系：
        │        • ID Token（JWT）：证明「你是谁」（身份凭证，OIDC规定）
        │        • AccessToken：访问资源的钥匙（可选JWT/随机串）
        │        • SessionID：传统有状态会话凭证（独立方案，非OIDC产物）
        └─ SSO单点登录、会话管理、策略鉴权
```

> 一句话层级记忆：
> **IDM ⊂ IAM；OIDC ⊂ IAM 的 AM 模块；JWT 是 OIDC 里 ID Token 的标准格式；SessionID 是另一套传统会话方案。**

# 二、完整端到端时序（企业员工 SSO 登录业务系统）
角色：HR 系统 → IDM → IAM (IdP 身份中心) → 业务应用（SP 服务提供方）

1. **入职阶段（IDM 工作，事前一次性）**
HR 录入新员工信息 → IDM 触发账号预配 (SCIM 协议)
→ 在 IdP、AD、各业务系统自动创建账号，分配角色、部门属性

> 这一步**还没登录**，只是建好身份档案。

2. **用户访问业务系统，发起 SSO（IAM-AM 开始工作）**
用户打开 OA 系统 (SP) → OA 检测未登录，跳转至 IAM 身份中心 IdP（OIDC 协议）
3. **IdP 做身份认证（AM）**
用户在 IdP 输入密码 / MFA，校验通过
4. **OIDC 协议下发令牌**
IdP 返回两类令牌：
   - `ID Token`：**JWT 格式**，包含 sub (用户唯一 ID)、姓名、过期时间等身份信息（证明是谁）
   - `Access Token`：访问用户信息接口的凭证（可以 JWT / 随机字符串）
5. **业务应用 (SP) 校验 JWT**
OA 拿到 JWT，校验签名，读取里面用户、角色信息，完成登录，创建应用侧会话（可选 Cookie/SessionID）
6. **员工离职（IDM 工作）**
HR 标记离职 → IDM 自动触发账号回收：禁用 IdP 账号、回收各系统权限、删除 / 冻结账号

> 后续再去 SSO 登录，IdP 直接拒绝认证。

# 三、关键名词一句话速查表
| 名词 | 定位 | 核心产出 / 作用 |
| --- | --- | --- |
| IDM | IAM 子集，身份生命周期管理 | 账号新建、变更、回收，身份主数据，SCIM 同步 |
| IAM | 整体身份访问管理平台 | IDM + AM；SSO、认证、鉴权、令牌发放 |
| OAuth2 | 授权协议 | 授权第三方拿资源，**不做身份认证**，输出 AccessToken |
| OIDC(OpenID Connect) | 基于 OAuth2 的身份认证协议 | OAuth2 + 身份认证；**ID Token 强制 JWT** |
| JWT | 令牌数据格式（不是协议） | OIDC 的 ID Token 标准载体；也可单独做 AccessToken / 自研登录凭证 |
| SessionID | 传统会话凭证（有状态） | 服务端存储会话；只一串随机编号，不带用户信息 |
| SCIM | 账号同步协议 | IDM 用来在各个系统自动创建 / 删除账号 |
| IGA | 身份治理 | IDM 增强版，权限审计、合规、权限风险分析 |

# 四、2 条对比分支：传统 Session 登录 VS OIDC SSO

## 方案 A：传统单体系统登录（SessionID，无 IAM）
用户提交账号密码 → 应用自身校验 → 服务端创建 session，返回 SessionID (cookie)

> 缺点：多系统无法单点登录；账号生命周期需要人工维护（没有 IDM）

## 方案 B：IAM+OIDC+JWT（企业 SSO 标准方案）
IDM 维护账号生命周期 → IAM IdP 统一认证 → OIDC 下发 JWT IDToken → 业务系统自动识别用户身份

> 优点：一套账号登录所有应用；入职离职权限自动流转，合规审计。

# 五、容易踩坑的误区汇总
1. ❌ OAuth2 ≠ 登录，OAuth 只是授权；**OIDC 才是用来做登录认证**
2. ❌ JWT 不是协议，只是字符串格式；OIDC 强制 IDToken 用 JWT，AccessToken 不强制
3. ❌ IDM≠IAM，IDM 只管账号生命周期，不管登录；登录认证属于 IAM 里 AM 模块
4. ❌ SessionID 和 JWT 不是协议，都是**凭证**，两套独立的会话思路
5. ❌ OpenID 2.0（老古董）不用 JWT；现在说的 OpenID 登录，一律是 OIDC

# 六、极简类比再巩固
- IDM = 人事部门：管档案、入职建卡、离职销卡、更新岗位
- IAM 大楼 = 人事部门 (IDM) + 门卫安检 (AM)
- OIDC = 门卫的一套标准化核验流程
- JWT (ID Token) = 门卫盖了公章的身份通行证（自带信息，验章即可）
- SessionID = 门卫登记的登记本编号，需要查后台登记本才能确认身份
